Wallou: building an emergency alert app with Ionic and Angular

When someone is in danger, every second counts. Wallou lets them send an alert with their GPS position in one tap, and gives responders the medical information they need.

By Mohamadou Lamine SarrOctober 22, 20267 min read

Wallou (from "wallu", to rescue in Wolof) is a mobile app I designed and built in 2020. The idea is simple: after an accident or a health scare, the user presses one button. The app gets their position and sends an alert to the server, which links it to their medical profile.

This article walks through the app's architecture and the technical choices behind each feature.

The stack

  • Ionic 3 and Angular for the interface and logic, in TypeScript.
  • Cordova to access phone features: GPS, storage, on-screen messages.
  • SQLite to keep the session and profile on the device.
  • A REST API for accounts, profiles and alerts, secured with a JWT.

The user journey

  1. Sign-up in two steps: first the account (name, email, login, password), then the medical profile.
  2. Medical profile: blood group, conditions, treatments, allergies, other information and two emergency contacts. The blood group list comes from the API, so it stays consistent with the server.
  3. Alert: a home screen with an emergency button. The alert goes out with the GPS coordinates, and a dialog confirms the sending to the user.

Token-based authentication

On login, the app sends the username and password to /authenticate. The server returns a token (id_token) that the app then adds to every protected call:

this.http.post(BASE_URL + 'authenticate', { username: login, password: pwd })
  .map(res => res.json())
  .subscribe(data => {
    const headers = new Headers();
    headers.append('Authorization', 'Bearer ' + data.id_token);
    // the token is stored locally for the next launches
    this.sql.setJson('token', data.id_token);
  });

On startup, the app looks for this token in local storage. If it is there, the user lands straight on the alert screen without logging in again. That is essential for an emergency app: you do not ask someone who needs help for a password.

Simple local storage with SQLite

I wrote a small Sql service that opens a SQLite database on the phone (through the Cordova plugin) or a WebSQL database in the browser during development. It exposes a key-value table and get, set, getJson and setJson methods:

set(key: string, value: string): Promise<any> {
  return this.query(
    'insert or replace into kv(key, value) values (?, ?)',
    [key, value]);
}

Every query goes through a single query method that turns SQLite's callback API into promises. The rest of the app stays readable.

The geolocated alert

The emergency button calls the geolocation plugin with a 20-second timeout, then builds the alert:

const alerte = {
  dateEnvoieAlerte: moment().format(),
  localisation: lat + '; ' + lng,
  interventionYN: false,
  rejetYN: false,
  resumeIntervention: '',
  uniteSecoursId: 1,
  usagerId: usager.id
};
this.http.post(BASE_URL + 'alertes', alerte, options);

The alert model goes beyond sending: it lets a rescue unit take the alert, accept or reject it, then summarize its intervention. The mobile app is only the first step of a full handling process.

Design choice

The medical profile is not sent with the alert, only the user reference. Responders look the profile up on the server. The alert stays small, which matters on a weak network.

What I would do differently today

  • An offline queue for alerts. Without a network, the alert should be kept on the phone and resent automatically, with an SMS fallback to the emergency contacts.
  • HTTPS everywhere and encrypted token storage: medical data is sensitive.
  • Capacitor instead of Cordova, and a recent Angular version.
  • Automated tests on the alert flow, the most critical part of the app.

What this project taught me

Wallou taught me to design an app around one critical moment: everything else (sign-up, profile, session) exists so that this moment happens without friction. I apply the same logic on ServiceNow today: a good portal or a good flow removes effort at the moment the user needs it.
