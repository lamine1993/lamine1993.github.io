Wallou : construire une application d'alerte d'urgence avec Ionic et Angular

Quand une personne est en danger, chaque seconde compte. Wallou permet d'envoyer une alerte avec sa position GPS en un geste, et de transmettre aux secours les informations médicales utiles.

Par Mohamadou Lamine Sarr22 octobre 2026Lecture : 7 min

Wallou (de « wallu », secourir en wolof) est une application mobile que j'ai conçue et développée en 2020 au sein de l'Incubateur UGB (Université Gaston Berger de Saint-Louis). Son idée est simple : en cas d'accident ou de malaise, l'utilisateur appuie sur un bouton. L'application récupère sa position et envoie une alerte au serveur, qui la rattache à sa fiche médicale.

Cet article décrit l'architecture de l'application et les choix techniques derrière chaque fonctionnalité.

La pile technique

  • Ionic 3 et Angular pour l'interface et la logique, en TypeScript.
  • Cordova pour accéder aux fonctions du téléphone : GPS, stockage, messages à l'écran.
  • SQLite pour garder la session et le profil sur l'appareil.
  • Une API REST pour les comptes, les fiches et les alertes, protégée par un jeton JWT.

Le parcours utilisateur

  1. Inscription en deux étapes : d'abord le compte (nom, email, identifiant, mot de passe), puis la fiche médicale.
  2. Fiche médicale : groupe sanguin, maladies, traitements, allergies, autres informations et deux contacts d'urgence. La liste des groupes sanguins vient de l'API, pour rester cohérente avec le serveur.
  3. Alerte : un écran d'accueil avec un bouton d'urgence. L'alerte part avec les coordonnées GPS, et une fenêtre confirme l'envoi à l'utilisateur.

L'authentification par jeton

À la connexion, l'application envoie l'identifiant et le mot de passe à /authenticate. Le serveur renvoie un jeton (id_token) que l'application ajoute ensuite à chaque appel protégé :

this.http.post(BASE_URL + 'authenticate', { username: login, password: pwd })
  .map(res => res.json())
  .subscribe(data => {
    const headers = new Headers();
    headers.append('Authorization', 'Bearer ' + data.id_token);
    // le jeton est gardé en local pour les prochains lancements
    this.sql.setJson('token', data.id_token);
  });

Au démarrage, l'application cherche ce jeton dans son stockage local. S'il existe, l'utilisateur arrive directement sur l'écran d'alerte, sans se reconnecter. C'est essentiel pour une application d'urgence : on ne demande pas un mot de passe à quelqu'un qui a besoin d'aide.

Un stockage local simple avec SQLite

J'ai écrit un petit service Sql qui ouvre une base SQLite sur le téléphone (avec le plugin Cordova) ou une base WebSQL dans le navigateur pendant le développement. Il expose une table clé-valeur et des méthodes get, set, getJson et setJson :

set(key: string, value: string): Promise<any> {
  return this.query(
    'insert or replace into kv(key, value) values (?, ?)',
    [key, value]);
}

Chaque requête passe par une seule méthode query, qui transforme l'API à callbacks de SQLite en promesses. Le reste de l'application reste ainsi lisible.

L'alerte géolocalisée

Le bouton d'urgence appelle le plugin de géolocalisation avec un délai maximal de 20 secondes, puis construit l'alerte :

const alerte = {
  dateEnvoieAlerte: moment().format(),
  localisation: lat + '; ' + lng,
  interventionYN: false,
  rejetYN: false,
  resumeIntervention: '',
  uniteSecoursId: 1,
  usagerId: usager.id
};
this.http.post(BASE_URL + 'alertes', alerte, options);

Le modèle de l'alerte va plus loin que l'envoi : il prévoit qu'une unité de secours la prenne en charge, l'accepte ou la rejette, puis résume son intervention. L'application mobile n'est que la première étape d'un circuit complet de traitement.

Choix de conception

La fiche médicale n'est pas envoyée avec l'alerte : seule la référence de l'usager l'est. Les secours retrouvent la fiche côté serveur. L'alerte reste légère, ce qui compte quand le réseau est faible.

Ce que je ferais autrement aujourd'hui

  • Une file d'attente hors ligne pour les alertes. Si le réseau manque, l'alerte devrait être gardée sur le téléphone et renvoyée automatiquement, avec un SMS de secours vers les contacts d'urgence.
  • HTTPS partout et un stockage chiffré du jeton : les données médicales sont sensibles.
  • Capacitor plutôt que Cordova, et une version récente d'Angular.
  • Des tests automatisés sur le parcours d'alerte, le plus critique de l'application.

Ce que ce projet m'a appris

Wallou m'a appris à penser une application autour d'un seul moment critique : tout le reste (inscription, fiche, session) existe pour que ce moment se passe sans friction. C'est la même logique que j'applique aujourd'hui sur ServiceNow : un bon portail ou un bon flux réduit l'effort au moment où l'utilisateur en a besoin.
